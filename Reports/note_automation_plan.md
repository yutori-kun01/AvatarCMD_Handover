# note 記事の自動化 — 現状の評価と改善計画

> 作成日: 2026-10-10 ／ 対象: avatar-cmd_v3（自動化ルール `note_article`・記事テンプレート・記事ジョブ）

## 実装状況（2026-10-11）

| フェーズ | 状況 | 未実装・残り |
|---|---|---|
| 1. 安全に完全自動にする | ✅ 公開前チェック（承認範囲）・有料ラインの扱い（無料 / 保留 / 書き直し）・作成と公開の分離（すぐ / N 時間後 / 曜日・時刻） | — |
| 2. テーマの自動補充 | ✅ テーマ候補のキュー（ナレッジ・反応の良い SNS 投稿・ペルソナから提案）・重複の回避（過去 90 日）・採用 / 全自動・残りが少ないときの自動補充 | — |
| 3. 成果から学ぶ | ✅ 記事ごとの PV・スキ・コメントの取得・テーマの学習・テンプレートの A/B・改善処理 / 効果検証の対象に note を追加 | 売上（購入数）と記事の紐付け（note に購入数の API が無いため、収益アイテムとの手動の紐付けが必要） |
| 4. 操作性 | ✅ 記事カレンダー（プレビュー・承認・日時変更・取り消し）・テンプレートから自動化・月額の見積もり | ドラッグでの日時変更、指示を付けた部分の書き直し |

注意: 記事ごとの統計（`/api/v1/stats/pv` の行の `key`）は非公式 API の形に依存します。取れないときは「統計に見つかりません」と記録し、学習はデータ不足として扱います（記事の作成は止めません）。

## 1. 現状

| 項目 | いまの動き |
|---|---|
| 起動 | 自動化ルール「note 記事」（時刻 or 間隔）→ 記事ジョブ `full` を登録 → worker が実行 |
| 内容 | テンプレート（構成・タイトルの付け方・有料/価格・有料ライン・タグ・画像・見出し画像・入稿のしかた）＋ルールのテーマ |
| テーマ | ルールに書いたテーマを **実行回数の順に使う**（`executionCount % topics.length`） |
| 入稿 | テンプレートの設定で **下書き保存** か **すぐに公開**。予約公開は画面からのみ |
| 品質チェック | なし（SNS 投稿にある投稿前チェック・Jev・承認範囲は記事には適用されない） |
| 成果の取得 | note はアカウント全体の累計 PV・スキだけを取得（`fetchInsights`）。**記事ごとの PV・スキ・売上は投稿データに紐付いていない** |
| 失敗時 | ジョブの失敗はルールのエラーとアクティビティに出る。有料ラインが入らなかったときは無料記事として入稿し、警告を残すだけ |

## 2. 課題

1. **テーマが尽きる・重なる**: テーマを書いた数だけで一周し、同じテーマの記事が繰り返し作られる。過去の記事との重複を見ていない。
2. **品質ゲートが無い**: 「すぐに公開」のテンプレートでは、事実誤り・誇大表現・ルール違反があっても、そのまま公開される。
3. **学習できない**: 記事ごとの成果（PV・スキ・購入）が無いため、改善ループもトピック学習も note に効かない。
4. **操作が分かれている**: テンプレートは「投稿・記事 > note 記事」、ルールは「自動化ルール」、結果は「投稿」一覧と、画面をまたいで設定・確認する必要がある。
5. **予約の流れが弱い**: ルールから予約公開（例: 毎週火曜 20:00 に公開、作成は前日）ができない。作成と公開の時刻が同じになる。
6. **有料記事の取りこぼし**: 有料ラインが入らないと黙って無料で出る。売上機会の損失に気付きにくい。

## 3. 改善案（優先順）

### フェーズ 1 — 安全に「完全自動」にする（小〜中規模）

- **記事の公開前チェック**: 執筆後に `reviewPost` 相当の記事用チェック（長文向けのプロンプト）を通す。
  ルールに SNS と同じ「承認範囲」（すべて自動 / NG のみ保留 / OK のみ公開）を持たせ、保留時は **note の下書きに保存してアクティビティで通知**（公開はしない）。
- **有料ラインの扱いを選べるように**: 「入らなければ無料で公開」/「入らなければ下書きで保留」/「AI に入れ直させる（1 回だけ再試行）」。
- **作成と公開を分ける**: ルールに「公開の時刻」（例: 作成の 12 時間後・指定曜日の 20:00）を追加し、既存の予約公開の仕組み（Avatar CMD が保持して時刻に入稿）につなぐ。前日に作っておき、確認したい人は時刻までに直せる。

### フェーズ 2 — テーマを自動で補充する（中規模）

- **テーマの自動提案キュー**: ナレッジ（RSS・YouTube の要点）、反応の良かった X / Threads の投稿、ペルソナのトピックから、AI が記事テーマを週に数件提案してキューに積む。
  ルールのテーマが空・残り少ないときはキューから使う。提案は画面で採用・却下・並べ替えできる（全自動にする場合は自動採用）。
- **重複の回避**: 過去 90 日の記事タイトル・テーマと類似度（bigram）を比べ、近いものは使わない。
- **SNS の反応 → 記事**: X で反応率が上位の投稿を「深掘り記事」のテーマ候補にする（投稿から記事への導線にもなる）。

### フェーズ 3 — 成果から学ぶ（中規模）

- **記事ごとの成果を取得**: note の `stats/pv` の記事ごとの PV・スキを、`externalPostId` で投稿データ（Content.engagement）に保存する。売上は収益アイテムと記事を紐付けて記録する。
- **学習への接続**: 今回入れた「トピックの学習（反応の良いトピックを優先）」と「改善の効果検証」を note にも適用する（指標は 7 日時点の PV あたりのスキ、有料記事は PV あたりの購入）。
- **テンプレートの比較**: 同じテーマ群で 2 つのテンプレート（構成・価格）を交互に使い、成果の良い方を自動で選ぶ（A/B）。

### フェーズ 4 — 操作性（UI）

- **「このテンプレートで自動化」ボタン**: テンプレートの画面から、ルール（頻度・テーマ・公開の時刻・承認範囲）をその場で作る。画面の行き来をなくす。
- **記事カレンダー**: 今後の作成予定・公開予定・保留中の記事を 1 画面で表示し、ドラッグで公開日時を変える・保留を承認する。
- **プレビューと差し戻し**: 保留中の記事を、画像・有料ラインの位置つきでプレビュー。「この指示で書き直す」で該当箇所だけ再生成。
- **コストの事前表示**: ルールの頻度 × テンプレート（画像の枚数・見出し画像）から、月額の見積もりを作成前に表示する（X API の見積もりと同じ形）。

## 4. 進め方の提案

1. フェーズ 1（公開前チェック・有料ラインの扱い・作成と公開の分離）— 完全自動にする前提条件なので最優先
2. フェーズ 4 の「このテンプレートで自動化」と記事カレンダー — 日々の操作が最も楽になる
3. フェーズ 3 の記事ごとの成果の取得 — 学習の土台
4. フェーズ 2 のテーマ自動提案 — 運用の手間をなくす

フェーズ 1 は既存の仕組み（`autoApprovalDecision`・予約公開・記事ジョブ）をそのまま使えるため、追加のスキーマ変更は不要です。
フェーズ 3 は note の非公式 API に依存するため、取得失敗時は学習を「データ不足」として扱い、記事作成は止めない設計にします。
