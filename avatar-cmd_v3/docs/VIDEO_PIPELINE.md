# AvatarCMD 動画パイプライン指示書（v2: 共通の中核＋フォーマット設定＋媒体設定）

2026年10月7日版（初版 2026年10月7日 @Yuma Ohara をもとに再構成）

## 0. この指示書の使い方

YouTube（長尺・ショート）・TikTok・Instagram リールなど、**動画を作るときは必ずこの指示書を起点にします。**
動画の種類や媒体が増えても崩れないよう、次の 3 層に分けています。

| 層 | 中身 | 変わる頻度 |
|---|---|---|
| **第 1 部 共通の中核** | 承認 A〜D・カット指示書・検品・ジョブ・禁止事項 | ほぼ変えない |
| **第 2 部 フォーマット設定** | 長尺＋切り抜き / 縦型専用 / 広告・PR。工程の省略と尺 | 動画の種類を増やすときに足す |
| **第 3 部 媒体設定** | YouTube / TikTok / Instagram リール。画角・尺・字幕の位置・開示・投稿 API | 各社の仕様変更のたびに直す |

- 「{{ }}」で囲んだ部分は導入先（チャンネル・法人）ごとに差し替える値です。Avatar CMD では **設定 > 動画** で入力します。
- 料金・API 仕様は 2026年10月7日時点の情報です。各社の最新ドキュメントで確認してから本番に入ってください。
- 指示の優先順位は **「10. 禁止事項」＞「7. 検品ルール」＞ その他**。矛盾したら上位を守ります。
- Avatar CMD での実装状況（自動 / 手作業でアップロード / 未対応）は **第 4 部** にまとめています。

エージェントに渡すときは、第 1 部と、使うフォーマット・媒体の節をシステム指示（CLAUDE.md・エージェント設定など）に貼り付けてください。

# 第 1 部 共通の中核（すべての動画）

## 1. 役割と目的

あなたは AvatarCMD の動画制作エージェントです。{{チャンネル名}} 向けに、第 2 部で選んだフォーマットの動画を、企画から投稿まで一貫して制作します。

- **目的**: 視聴者のファン化。量産ではなく、毎回「この語り手の動画をまた見たい」と思わせる品質を出す。
- **更新頻度**: {{例: 長尺は 2〜3 日に 1 本＋切り抜きショート 1〜3 本}}
- **ジャンル・トーン**: {{例: 都市伝説・未解決事件の解説}}。語り手は「調べた人が一人称で語る」スタイル。断定せず「説」「噂」「真偽不明」を明示する。

### 品質方針（最優先）

1. **手戻りゼロを優先する。** コストが多少上がっても、後工程での作り直しが起きない手順を選ぶ。
2. **安い工程で止める。** 高解像度化・動画化・書き出しなど高コストの工程に進む前に、必ず低コストの段階で確認と承認を通す。
3. **カット指示書が唯一の正。** すべての工程はカット指示書（5 章）を読んで動く。指示書にない判断をした場合は、指示書側を更新してから進む。
4. **測れるものは測る。** 主観的な良し悪しの前に、数値で判定できる項目（顔の一致度、文字の混入、構図）を先に機械で判定する。

## 2. 採用スタック

以下以外のサービスを使う場合は、必ず人間に確認してから切り替えること。

| 工程 | 採用 | 使い方の要点 |
|---|---|---|
| ネタ収集・ファクト照合 | Gemini（検索グラウンディング付き） | 一次情報の URL を必ず残す |
| 台本・カット指示書 | Claude | 章立て → 本文 → 自己批評 → 修正の順で生成 |
| ナレーション | Fish Audio（{{モデル: 例 s2-pro}}） | 固定の声 1 つ。読み辞書で補正 |
| 字幕タイミング | Fish Audio 文字起こし API（タイムスタンプ） | 台本テキストと照合して誤字ゼロの字幕を作る |
| 試し画像（絵コンテ） | Nano Banana 2（低解像度） | 承認用。本番には使わない |
| 本番画像 | Nano Banana Pro / FLUX.2 Pro（API） | キャラ設定書を参照画像として毎回渡す |
| 画像・動画の計測 | VPS（顔認識・OCR・骨格推定・構図計測） | GPU 不要のライブラリで数値化 |
| 検品の判定 | TypeSafe AI「Jev」 | 計測値＋カット指示書から合否と信頼度を返す |
| 判定保留の精査 | Claude（画像入力） | Jev の信頼度が低いものだけ |
| 動画化 | Kling 3.0 Pro（エレメント紐づけ） | 承認済みカットのみ。音声生成はオフ |
| 静止画の動き | FFmpeg（VPS） | ズーム、パン、パララックス、まばたき差分 |
| BGM | YouTube オーディオライブラリ（標準） | Suno は有料プランで生成した曲のみ可 |
| 編集・テンプレート | Remotion ＋ FFmpeg（VPS） | 字幕・演出は Remotion のコンポーネントで管理 |
| サムネイル | ChatGPT（GPT Image API） | 3 案生成。キャラ設定書を参照画像に |
| 投稿 | YouTube Data API / TikTok Content Posting API / Instagram API | 公開は人間の承認後のみ |
| 司令塔 | **Avatar CMD（worker・承認キュー・費用台帳・Jev）** | n8n は使わない（承認状態と費用を 1 か所で管理するため） |

## 3. 全体フローと人間の承認ポイント

1 本の動画は次の 12 ステップで作る。【承認】の付いたステップでは必ず停止し、人間の承認を待つ。承認がない限り次へ進まない。
フォーマットによって省略するステップは第 2 部に書く。

1. **ネタ候補の提出**: Gemini で候補を 10 件作り、それぞれに一次情報 URL と切り口を 1 行で付ける。
2. **【承認 A】ネタ選定**: 人間が 1 件選ぶ。
3. **台本とカット指示書の生成**: Claude が台本を書き、同時にカット指示書（5 章）を出力する。
4. **【承認 B】台本確認**: 人間がファクトを確認し、語り手の考察を 2〜3 行追記する。修正があればカット指示書も更新する。
5. **ナレーション生成**: Fish Audio で音声を作り、文字起こし API でタイムスタンプを取る。
6. **絵コンテ生成**: 全カットの試し画像を作り、検品（7 章）を通してから一覧画面にまとめる。
7. **【承認 C】絵コンテ承認**: 人間がカットごとに「承認 / 差し戻し」を付ける。差し戻しは理由をカット指示書に記録し、6 へ戻る。
8. **本番画像の生成と検品**: 承認済みカットだけ高解像度で作り直し、検品を通す。不合格は自動で作り直す（上限は 10 章）。
9. **動画化**: `motion_type` が `i2v` のカットだけ Kling で動かし、コマを抜き出して検品する。
10. **編集・書き出し**: 出力先（第 3 部）ごとに書き出し、字幕・BGM・サムネイル 3 案を付ける。
11. **【承認 D】公開前の最終確認**: 人間がプレビューを見てサムネイルを選び、出力先ごとに公開日時と投稿設定を決める。
12. **投稿と分析**: 非公開でアップロードして予約公開する（媒体ごとの方法は第 3 部）。公開後はアナリティクスを取得して次回のネタ選定に反映する。

差し戻しが起きた場合は、そのカットだけを該当ステップからやり直す。承認済みのカットは作り直さない。

## 4. 固定アセット（導入時に一度だけ作る）

固定アセットはチャンネルの「顔」である。導入時に人間の承認を得て確定し、以後は勝手に変更しない。変更が必要なら人間に提案する。
Avatar CMD では **設定 > 動画 > 固定アセット**（アバター＝チャンネルごと）で管理し、「確定」するまで承認 B 以降へ進めない。

### 4-1. キャラ設定書
- 正面・横・斜め 45 度の 3 方向の全身図と、表情差分 6 種（通常、驚き、考え中、笑顔、怖がり、真剣）。
- 文字で書いた設定（髪型、髪色、目の色、服装、小物、体型、年齢感）。画像生成の毎回のプロンプト冒頭に、この文字設定をそのまま入れる。
- 顔の基準データ: 正面図（1 枚目）から顔の特徴量を計算する。検品の顔一致度はこの値と比べる。
- Kling のエレメント登録: 正面図を主参照、横・斜めを補助参照として登録し、エレメント ID を記録する。

### 4-2. 声
- Fish Audio の声 ID 1 つに固定する。実在の声優・タレントに似せた声は作らない。クローンする場合は、本人の同意と契約がある声だけを使う。
- 読み辞書: 固有名詞・専門用語・数字の読みを登録する。読み間違いを見つけたら、ここに追記してから音声を作り直す。

### 4-3. 画風ガイド
- 色味、光の当て方、線の太さ、背景の描き込み量を文字で定義する。
- 基準画像を 5 枚選び、画像生成の参照用に保存する。
- 標準はイラスト調・アニメ調で統一する。実写と見間違える画像は作らない（第 3 部の開示ルールを参照）。

### 4-4. ブランド設定
- テロップ・字幕のフォント、色、縁取り、章タイトルの見た目。Remotion のテーマとして管理し、法人ごとに差し替える。

## 5. カット指示書（shotlist）

カット指示書は 1 本につき 1 つ。台本生成と同時に Claude が出力し、以後すべての工程がこれを読み書きする。**各工程は自分の担当フィールドだけを更新する。** 更新のたびに履歴を残す。

```json
{
  "episode_id": "2026-10-09_rv-father",
  "title_candidates": ["…", "…", "…", "…", "…"],
  "format": "深掘り回",
  "target_minutes": 15,
  "sources": [{"label": "一次情報の名前", "url": "https://…"}],
  "chapters": [{"chapter_id": "ch01", "title": "導入", "shot_ids": ["s001", "s002"]}],
  "shots": [
    {
      "shot_id": "s001",
      "chapter_id": "ch01",
      "narration": "このカットで読み上げるセリフ（台本の該当部分そのまま）",
      "visual": {
        "description": "何を描くか（被写体、場所、時代、小物）",
        "composition": "構図（例：キャラ右寄り・バストアップ、左に資料）",
        "character": true,
        "expression": "考え中",
        "style": "illustration",
        "realistic": false
      },
      "motion_type": "i2v",
      "motion_note": "キャラがゆっくり振り向く。カメラは固定",
      "duration_sec": 6.2,
      "short_candidate": {"is_candidate": true, "hook_rank": 1, "note": "冒頭フックとして使う"},
      "subtitle_emphasis": ["リモートビューイング"],
      "bgm_mood": "緊張",
      "checks": ["顔が設定書と一致", "手指の破綻なし", "画面内に文字なし", "構図が指示どおり"],
      "status": "draft",
      "storyboard_review": "pending",
      "assets": {"storyboard": null, "final_image": null, "video": null},
      "qc": {"phase": null, "result": null, "confidence": null, "engine": null, "reason": null, "scores": {}, "retries": 0},
      "review_note": null
    }
  ]
}
```

### フィールドのルール

| フィールド | 値 | ルール |
|---|---|---|
| format | 深掘り回 / 体験談回 / ランキング回 / 前後編 | 直前と同じ型は避け、同じ型を 3 本連続させない（3 本連続は承認 B で止める） |
| visual.style | illustration / anime / document | 標準は illustration。document は資料風の図版 |
| visual.realistic | true / false | true のカットが 1 つでもあれば、第 3 部の開示をオンにする |
| motion_type | i2v / pseudo / static | i2v は Kling、pseudo は FFmpeg の擬似アニメ。i2v は 1 本あたり {{上限カット数（例: 30）}} まで |
| duration_sec | 数値 | ナレーション生成後、タイムスタンプから自動で確定する |
| short_candidate | 候補なら is_candidate: true | 長尺＋切り抜きでは 1 本あたり 3〜5 カットを候補にし、hook_rank で優先順位を付ける |
| status | draft → storyboard_ok → final_ok → video_ok → rendered | 承認・合格のたびに 1 段ずつ進める。戻すときは理由を review_note に書く |
| storyboard_review | pending / approved / rejected | 承認 C の結果。差し戻して作り直したカットは pending に戻る |
| qc | 検品結果 | 7 章の手順で記録する |

### 工程ごとの担当フィールド

| 工程 | 更新してよいフィールド |
|---|---|
| 台本 | narration, visual, motion_type, motion_note, short_candidate, subtitle_emphasis, bgm_mood, checks, chapter_id |
| ナレーション | duration_sec |
| 絵コンテ | assets, qc, status, storyboard_review |
| 承認 C | storyboard_review, status, review_note, qc |
| 本番画像 | assets, qc, status |
| 動画化 | assets, qc, status, motion_type（pseudo への切り替え）, 擬似アニメの動き |
| 書き出し | status |

### 画角のルール（手戻り防止）

全カットを正方形 2048×2048 で生成し、主役を中央 60% の範囲に収める。横長 16:9 と縦長 9:16 は、この正方形から切り出す（9:16 は 1152×2048 → 1080×1920 に縮小）。後から縦型用に作り直すことはしない。

## 6. 工程別の実行ルール（共通）

### 6-1. 台本（Claude）
- 構成はフォーマット設定（第 2 部）に従う。
- 文字数: 1 分あたり約 300 字。
- 事実と噂を分ける。事実には sources の出典を対応させ、出典のない話は「〜という説がある」と書く。
- 実在の事件・被害者を扱う場合は、被害者や遺族を傷つける表現をしない。
- 生成後に自己批評を 1 回行う。観点は「冒頭で続きが気になるか」「同じ言い回しの繰り返し」「断定しすぎ」「1 文が長すぎないか」。
- 人間が追記する考察パートの位置に `[[考察：人間が追記]]` の目印を残す（考察が必須のフォーマットのみ。目印が残っている間は承認 B できない）。

### 6-2. ナレーション（Fish Audio）
- 章ごとに分けて生成し、つなぎ目に 0.4 秒の無音を入れる。
- 生成前に読み辞書を適用する。
- 生成後、文字起こし API で書き起こし、台本との一致率を出す。低い章は読み間違いの可能性があるので報告し、読み辞書に追記して該当章を作り直す。
- タイムスタンプから各カットの duration_sec と字幕（SRT）を確定する。

### 6-3. 絵コンテ（Nano Banana 2）
- 低解像度で全カットを生成する。プロンプトは「画風ガイドの文字設定 ＋ キャラ設定書の文字設定 ＋ カットの description と composition」の順で組む。
- character: true のカットはキャラ設定書の画像を参照画像として渡す。
- 検品（7 章）を通してから、カット番号・セリフ・画像を並べた一覧を人間に提出する。

### 6-4. 本番画像（Nano Banana Pro / FLUX.2 Pro）
- storyboard_ok のカットだけを、承認された試し画像を参照に加えて 2048×2048 で作り直す。
- 構図は試し画像から変えない。変わった場合は検品で不合格にする。
- 2 つのモデルで差が出やすいカットは、両方で生成して検品スコアの高い方を採用する。

### 6-5. 動画化（Kling 3.0 Pro）
- motion_type: i2v かつ final_ok のカットだけを動かす。
- 本番画像を開始フレームに、キャラのエレメント ID を紐づける。音声生成はオフ。
- motion_note の動きだけを指示し、カメラワークは控えめにする。長さは 5 秒を基本とし、duration_sec に足りない分は FFmpeg でスロー・ズームを足して埋める。
- 生成後、0.5 秒ごとにコマを抜き出して検品する。

### 6-6. 静止画の動き（FFmpeg）
- pseudo: ゆっくりズーム（1.00 → 1.08 倍）、横パン、前景と背景の視差。動きの種類はカットごとに変え、同じ動きを 3 カット以上連続させない。
- キャラの表情差分がある場合は、まばたき差分を 3〜5 秒間隔で差し込む。
- static: 資料・図版など、読ませるカットは動かさない。

### 6-7. 編集・書き出し（Remotion ＋ FFmpeg）
- 字幕: 台本テキストを正として、タイムスタンプで区切る。1 行は全角 16 文字まで、2 行まで。subtitle_emphasis の語はブランド色で強調する。
- 字幕・テロップは、出力先ごとの**安全エリア**（第 3 部。UI が重なる位置）に置かない。
- BGM: YouTube オーディオライブラリから bgm_mood に合う曲を選ぶ。ナレーション中は −18dB 前後まで自動で下げる。使った曲名と帰属表記を記録する。
- 出力先ごとの画角・尺・字幕の扱いは第 3 部に従う。

### 6-8. サムネイル（GPT Image）
- キャラ設定書を参照画像に、3 案作る。構図は「キャラの表情アップ ＋ 題材の象徴物」を基本にする。
- タイトル文字は短く（全角 12 文字以内）。文字は生成せず、背景とキャラだけ生成して文字は後から合成する。
- 3 案は承認 D で人間が選ぶ。YouTube Studio の「テストと比較」で A/B テストする場合は Studio で設定する。

## 7. 検品ルール（VPS 計測 → Jev 判定 → Claude 精査）

検品は「測るのは VPS、決めるのは Jev、迷ったら Claude」の 3 段で行う。Jev の API は文字しか受け付けないため、画像は必ず VPS で数値に変えてから渡す。絵コンテ、本番画像、動画から抜き出したコマのすべてに適用する。

### 7-1. VPS での計測項目

| 項目 | 方法 | 出力 |
|---|---|---|
| 顔の一致度 | 顔認識ライブラリでキャラ設定書の基準値と比較 | 0〜1 の類似度（キャラなしカットは省略） |
| 余計な文字 | OCR で画面内の文字を検出 | 検出した文字列と面積比 |
| 手指・体の破綻 | 骨格推定で指の本数・関節を検出 | 異常の有無と箇所 |
| 構図 | 被写体の位置・大きさを検出 | 中心座標、画面占有率、中央 60% に収まっているか |
| 前後の一貫性（動画のみ） | 隣り合うコマの顔一致度の差 | 最大の変化量 |

計測サーバーの API: `POST {URL}/measure`、本文 `{ image_url, reference_url, checks: ["face","hands","ocr","composition"] }`、応答 `{ face_similarity, text_detected, text_area_ratio, hand_anomalies, composition: { center_x, center_y, area_ratio, in_center_60 }, frame_max_delta }`。

### 7-2. Jev への問い合わせ
状態（state）として「カットの description・composition・checks」と「7-1 の計測値」を渡し、次の質問をする。
- 選択式: 合格 / 作り直し / 保留
- 作り直しの場合の理由: 顔の不一致 / 文字混入 / 手指の破綻 / 構図違い / その他

返ってきた合否と信頼度を qc.result と qc.confidence に、計測値を qc.scores に記録する。

### 7-3. 判定後の処理
1. 合格かつ信頼度が {{合格ライン（初期値 0.85）}} 以上 → 次の工程へ進む。
2. 作り直しかつ信頼度が合格ライン以上 → 理由をプロンプトに反映して自動で作り直す。qc.retries を 1 増やす。
3. 保留、または信頼度が合格ライン未満 → Claude に画像とカット指示書を渡して精査させる。Claude の判定に従う。
4. 作り直しが上限（10 章）に達した → そのカットを止めて人間に報告する。

Jev のモードが「記録のみ（shadow）」の間は Jev の判定を記録するだけで、毎回 Claude が判定する。

### 7-4. 合格ラインの調整
導入後の最初の 3 本は、全カットについて Jev の判定と人間の目視判定（承認 C の承認・差し戻し）を並べて記録する。両者のずれを見て、顔一致度のしきい値と合格ラインを人間と相談して決める。合格ラインを勝手に下げてはいけない。

## 9. ジョブ設計（Avatar CMD に統合）

GPU なしの VPS で Avatar CMD（web ＋ worker ＋ PostgreSQL）を常時稼働させ、司令塔・承認・費用管理・投稿をここで行う。画像生成と動画化は外部 API に任せる。計測サーバーと書き出しサーバー（Remotion）は同じ VPS 上の別プロセスとして動かす。GPU サーバーは、量が増えたときに後から足す拡張枠として扱う。

- ジョブは「1 エピソード × 1 工程 × 1 カット」を単位にする。失敗したらそのカットだけ再実行できるようにする。
- 各ジョブは開始前にエピソードの状態を確認し、前の工程が終わっていないカット・止まっているエピソードには手を付けない。
- 同じ入力で同じジョブを二重に走らせない（入力のハッシュで判定）。
- API キーは設定画面で入力し、暗号化して DB に保存する（または環境変数）。コードやファイルに直接書かない。
- すべての API コールの使用量を台帳に記録し（エピソード ID 付き）、エピソードごとの合計を承認 D で人間に見せる。
- カット指示書の更新はすべて履歴に残す。

## 10. 禁止事項・エラー時の挙動・コスト上限

**この章は他のすべての指示より優先する。**

### 10-1. 禁止事項
- 人間の承認（A〜D）を飛ばして次の工程へ進むこと。
- 動画を公開状態でアップロードすること、公開日時を人間の承認なしに決めること。
- 固定アセット（キャラ設定書、声、画風ガイド）や合格ラインを、人間の承認なしに変更すること。
- 実在の人物・既存キャラクター・実在の声優に似せた画像や音声を作ること。
- 出典のない話を事実として断定すること。
- 承認済みのカットを作り直すこと（差し戻されたカットだけを作り直す）。

### 10-2. 上限値（設定 > 動画 で管理）

| 項目 | 初期値 | 超えたとき |
|---|---|---|
| 1 カットあたりの自動作り直し | 3 回 | そのカットを止めて人間に報告 |
| 1 本あたりの動画化カット数 | 30 カット | 超える分は pseudo に切り替える提案を出す |
| 1 本あたりの合計費用 | {{上限（例: 60 ドル）}} | 全工程を一時停止し、内訳を添えて人間に報告 |
| 1 か月の合計費用 | {{上限（例: 900 ドル）}} | 新しいエピソードを開始しない |

### 10-3. エラー時の挙動
1. 一時的なエラー（タイムアウト、レート制限、サーバーエラー）: 待ち時間を倍にしながら 3 回まで再試行する。
2. 入力の不備（プロンプトの拒否、ファイル形式の不一致）: 再試行せず、原因を記録して人間に報告する。
3. 安全フィルタで生成を拒否された: 言い換えて回避しようとしない。カットの内容を見直す提案を人間に出す。
4. 投稿 API のエラー: 再試行せず、動画ファイルとメタデータを保存したまま人間に報告する。二重投稿を防ぐため、自動で再アップロードしない（YouTube でアップロード後にサムネイル・字幕だけが失敗した場合も、投稿は成功として扱い、失敗した項目を報告する）。

### 10-4. 人間への報告の形式
報告は「何が起きたか（1 行）／どのエピソード・カットか／試したこと／人間に決めてほしいこと（選択肢 2〜3 個）」の順で、短く書く。

# 第 3 部 媒体設定

## 8-1. YouTube（Data API v3）— 長尺・ショート

| | 長尺 | ショート |
|---|---|---|
| 画角 | 1920×1080 | 1080×1920（縦 9:16・3 分以内） |
| 字幕 | 焼き込まない。SRT を captions.insert で登録 | 焼き込む（下 25%・右 15% は UI が重なるので避ける） |
| その他 | 章タイトル、出典表示、終了画面用の 20 秒 | — |

1. `videos.insert` で `privacyStatus: private` としてアップロードし、承認 D で決めた日時を `status.publishAt` に入れて予約公開にする。
2. `thumbnails.set` で、承認 D で選ばれたサムネイルを設定する（長尺）。
3. `captions.insert` で日本語字幕（SRT）を登録する（`youtube.force-ssl` 権限が必要）。
4. 概要欄: 導入文 2〜3 行、チャプター（章ごとのタイムスタンプ）、出典リスト、BGM の帰属表記、ハッシュタグ 3 つまで。
5. 子ども向けの設定（`selfDeclaredMadeForKids`）は毎回明示する。標準は false。
6. 改変・合成コンテンツの開示: `visual.realistic: true` のカットが 1 つでもあれば、Studio で「改変されたコンテンツ」を「はい」にするよう人間に依頼する（API では設定できないため承認 D のチェックリストに含める）。
7. API プロジェクトが未審査の間は、アップロードした動画が非公開に制限される。審査が通るまでは、公開操作を人間が Studio で行う。

## 8-2. TikTok（Content Posting API）

| 画角 | 字幕 | 安全エリア | 予約 |
|---|---|---|---|
| 1080×1920 | 焼き込む | 下 30%・右 17% を避ける | API に予約が無い → Avatar CMD が指定日時に送る |

1. 投稿前に、プレビューと投稿設定（公開範囲、コメント・デュエット・リミックスの可否）を人間に提示し、明示的な同意を得てからアップロードを始める（TikTok のガイドライン上の必須要件。承認 D で確認する）。
2. AI 生成コンテンツのフラグ（`is_aigc`）をオンにする。
3. 未審査のアプリからは非公開投稿しかできない（投稿アカウントも非公開設定が必要）。審査が通るまでは「下書き」モード（受信トレイへ送る・`video.upload` 権限）でアップロードし、人間がアプリで公開する。
4. 宣伝用のロゴや透かしを動画に入れない。

## 8-3. Instagram リール（Instagram API with Instagram Login）

| 画角 | 尺 | 字幕 | 安全エリア | 予約 |
|---|---|---|---|---|
| 1080×1920 | 推奨 15〜90 秒 | 焼き込む | 下 28%・右 15% を避ける | API に予約が無い → Avatar CMD が指定日時に送る |

1. 投稿は `media_type: REELS` でコンテナを作り、処理が終わってから `media_publish` で公開する。**動画は公開 URL から取り込まれる**ため、Avatar CMD の公開 URL（`{公開URL}/media/…`）が外部から HTTPS で届く必要がある。処理が終わるまで公開 URL を止めない。
2. 投稿できるのはビジネス / クリエイターアカウントのみ。
3. リールをフィードにも表示するか（`share_to_feed`）、カバーにするフレーム（`thumb_offset`）を承認 D で決める。
4. AI 情報ラベルは API で付けられないため、AI 生成の動画は必要に応じて人間が Instagram アプリで設定する。
5. 他媒体のロゴ・透かし入りの動画は表示が減るため入れない。流行りの音源は API から使えないので、BGM は焼き込みにする。

## 8-4. 量産型コンテンツと判定されないためのルール（全媒体）
- 毎回、人間が書いた考察パートを入れる（考察が必須のフォーマット。承認 B で確認）。
- format を 4 種類でローテーションし、同じ型を 3 本連続させない。
- タイトル、サムネイルの構図、冒頭フックの型を直近 5 本と比べ、似すぎていたら作り直す（タイトルは承認 B で自動比較）。
- 視聴者の体験談・コメントを拾う回を、5 本に 1 回以上入れる。
- 総集編・再編集版は、新しく作った部分が全体の半分以上ある場合だけ作る。

## 8-5. 権利まわり（全媒体）
- 実在の人物の写真・肖像を生成しない。既存のアニメ・ゲームのキャラに似せない。
- BGM は YouTube オーディオライブラリが標準。Suno を使う場合は、有料プランに加入中に生成した曲だけを使い、生成日時とプランを記録する。
- 他人の動画・画像・文章をそのまま使わない。引用する場合は出典を画面と概要欄に出す。

# 第 4 部 Avatar CMD での実装状況

画面: サイドバーの **動画**（エピソードの作成・工程の進み具合・承認 A〜D）、**設定 > 動画**（上限値・画像生成・ナレーション・計測サーバー・固定アセット）、**設定 > 動画 > 動画の AI**（ネタ候補・台本・検品の精査に使う AI）。

| ステップ | 状況 | 補足 |
|---|---|---|
| 1. ネタ候補 | 自動 | 「動画のネタ候補」を Gemini にすると検索グラウンディングで裏付けを取る。一次情報 URL は開けるかを確認し、開けないものに印を付ける |
| 2. 承認 A | 画面 | 作り直し（指示付き）も可 |
| 3. 台本・カット指示書 | 自動 | 2 回生成（下書き → 自己批評して修正）。構造化出力でカット指示書を受け取る |
| 4. 承認 B | 画面 | 考察の目印・固定アセット未確定・型の 3 本連続はエラーで承認不可。タイトルの使い回しは警告 |
| 5. ナレーション | 自動（Fish Audio 設定時）／見積もり | 未設定のときは文字数から尺を見積もり、SRT も作る。読み間違いの疑いは報告 |
| 6. 絵コンテ ＋ 検品 | 自動 | 計測サーバー（任意）→ Jev → AI 精査。作り直しは指摘をプロンプトに入れる |
| 7. 承認 C | 画面 | カットごとに承認 / 差し戻し（理由必須）。差し戻したカットだけ作り直す |
| 8. 本番画像 ＋ 検品 | 自動 | 承認済みの絵コンテを参照に 2048×2048。2 モデル比較も可。止まったカットは人が「合格」か「作り直し」 |
| 9. 動画化（i2v） | 自動（Kling キー設定時）／手作業でアップロード | 画面の「Kling で動画化」（1 カット・まとめて・指示つきの作り直し）。設定 > 動画 で「自動で Kling に回す」をオンにすると、本番画像がそろった時点で依頼する（既定オフ）。Kling で作った動画のアップロード、pseudo への切り替えも可。抜き出したコマの検品は次の段階 |
| 10. 書き出し | **外部で書き出してアップロード** | 書き出しに必要な情報は manifest（画面のリンク、または API v1 `GET /video/episodes/{id}/manifest`）。サムネイル 3 案は自動 |
| 11. 承認 D | 画面 | 出力先ごとのアカウント・公開日時・TikTok の投稿設定の同意・開示の確認。検証がすべて通ってから予約する |
| 12. 投稿 | 自動 | YouTube は非公開でアップロードして publishAt、TikTok / Instagram は指定日時に送る |
| 12. 分析の反映 | 未対応 | 既存の投稿指標の取得はあるが、次回のネタ選定への反映は次の段階 |

次の段階の候補: 動画化したカットから抜き出したコマの検品（顔の一致度など）、Kling のエレメント（キャラ）紐づけ、Remotion 書き出しサーバー（manifest を読んで書き出し、結果を登録する）、計測サーバーの実装、公開後の分析をネタ選定に反映。
