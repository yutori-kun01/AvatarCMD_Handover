# 判定レイヤー（TypeSafe Jev）— Avatar CMD v3

生成（文章を書く）は LLM、**判断（選ぶ・採点する・可否を決める）は Jev** に分けます。
Jev は答えを確率付きで返すので、「どれくらい確かか」を見てコード側のルールで処理を決められます。

## 設定

**設定 > システム > 判定（TypeSafe Jev）**

| 項目 | 内容 |
|---|---|
| TypeSafe API キー | 暗号化して DB に保存。未入力なら `.env` の `TYPESAFE_API_KEY` |
| モデル | 空欄なら `jev-1.13.0`（本番は固定バージョン推奨。`jev-latest` は変化を受け入れる場合のみ） |
| モード | **記録のみ（shadow）**: 判定を記録するだけ／**反映（gate）**: 判定を処理に使う／**使わない** |

**キーが無い・「使わない」のときは Jev を一切呼ばず、これまでどおり動きます**（投稿前チェックは LLM、引用の判定は「引用投稿」用途の LLM、改善か継続かはコードのルール）。
Jev の呼び出しに失敗した場合も、エラーを記録して既存の流れで続行します。

## Jev を使う判断

| 判断 | 使われる場所 | 質問 | 反映のしかた（コード側） |
|---|---|---|---|
| 投稿の可否 `post_gate` | 自動化ルールの生成時・投稿画面の「AIでチェック」 | 公開してよいか（publish / review / hold）、口調の一致、宣伝色、重複、ブランドリスク | gate モードの自動投稿で、hold / review・確信度 60% 未満・ブランドリスク高・重複 70% 以上・口調不一致なら下書きへ |
| 引用候補 `quote_candidate` | 引用候補の探索 | 方向性の一致（aligned / partial / opposed / unrelated）、引用する価値、関わるリスク、添える観点（知見 / 体験） | aligned 60% 以上・価値 60% 以上・リスク低 のものだけ引用案を作る |
| 改善か継続か `performance` | 自動化ルールの分析（1日1回＋手動） | 継続 / 改善 / 停止、改善するなら何を（書き出し・トピック・形式・時間帯・長さ）、データは十分か | 提案として表示するだけ（ルールは自動で変えない） |

閾値はすべてコード（`post-decision.ts` の `POST_GATE_THRESHOLDS`、`quotes.ts` の `QUOTE_RULES`、`performance.ts`）にあり、Jev のプロンプトには入れていません。
数値の集計（中央値・比率）もコードで行い、Jev には結果だけを渡します。

## 精度の検証（shadow → gate の判断材料）

すべての判定を `decision_events` テーブルに記録します（入力の要約・答え・確信度・所要時間・トークン数・エラー）。
下書きを **承認** すると `approved`（修正して承認は `approved_edited`）、**削除** すると `rejected` が人の判断として記録されます。

設定画面に直近30日の判定件数・エラー件数・人の判断との一致率を表示します。
**一致率が十分（目安: 100件以上で 90% 以上、誤って公開すべきでないものを publish と判定した件数が 0）になってから gate に切り替えてください。**

## 関連する機能

### 投稿の反応（指標）の収集
worker が 10 分ごとに確認し、公開から 14 日以内の投稿を取得します（〜48時間: 6時間ごと／以降: 24時間ごと）。

- **X**: 自分の投稿一覧（`GET /2/users/{id}/tweets` の public_metrics）。**Owned Reads: 1件 $0.001**
- **Threads**: 投稿ごとのインサイト（views / likes / replies / reposts / quotes / shares）。
  権限 `threads_manage_insights` が必要（追加前に接続したアカウントは再接続）。
  フォロワー100人未満など Meta の条件を満たさない間は、理由を記録してスキップします。

### 引用投稿の候補（X）
投稿画面の「引用投稿（X のタイムラインから）」、**自動化ルール「X の引用投稿」**（v3.6〜。対象条件・頻度・承認方法をルールごとに設定）、
または X アカウントの設定「引用候補の自動探索」（12 / 24 時間ごと。引用ルールのあるアカウントでは動かない）。

1. ホームタイムラインを取得（`GET /2/users/{id}/timelines/reverse_chronological`。**Owned Reads: 1件 $0.001**。前回の続きから）
2. コードで除外: リポスト・返信・引用、自分の投稿、短すぎる投稿、48時間より古い投稿、7日以内に引用した相手
3. 反応の大きい順に最大 10 件を判定（Jev / 無ければ LLM）
4. 通過したもの（最大 3 件）を「引用投稿」用途のモデルで執筆: 共感・肯定＋知見 or 体験を1つ。
   **体験はプロフィール・知識に書かれた事実に基づくものだけ**（作り話はさせない）
5. 投稿前チェックを通して **下書き**（引用ルールで「自動投稿」を選んだ場合だけ、承認範囲に従って予約キューへ）
6. 投稿時は `quote_tweet_id` を使わず、**元投稿の URL を本文に直接入れる**（URL は正規化して1回だけ・前後に半角スペース。
   本文の整形が終わってから入れるので、改行の除去・ツリー分割で URL やスペースが崩れない）。実際に引用カードとして表示されるかは未検証
7. 同じ元投稿は同じアバターで二度使わず、既定では別のアバターが引用済みの投稿も使わない

**Owned Reads の条件**: 認証した X アカウントが、その開発者アプリの所有者であること。
アバターごとに「設定 > アカウント > このアバター専用のアプリを使う」で、その X アカウント自身の開発者アプリを登録して接続してください。
条件を満たさない場合は通常の読み取り（1件 $0.005）になります。

X の自動化ルールでは、自動の引用・返信に制限があります。引用ルールの既定は「下書き（承認制）」です。
「自動投稿」も選べますが、X の規約・自動化ルールに沿うかを確認したうえで使ってください（画面にも警告を表示します）。

### 改善か継続か
自動化ルールごとに、直近 30 日の投稿の反応を **同じアバター・同じプラットフォームの他の投稿の中央値** と比べます
（比較対象が無い場合はルールの前半と後半を比較）。表示回数が取れていれば反応率、無ければ反応数で比べます。
指標のある投稿が 3 件未満なら「データ不足」とし、Jev は呼びません。
